把"AI 学长"做成 App 的新主入口

这不是又一个聊天框。AI 学长 Tab 是一个由多个 Agent 组成的工作台—— 上层是结构化能力（找搭子、选课、就业经验、二手、问答），下层是兜底自由对话； 背后接的是种草 / 同校 Tab 的全量 UGC 与公开校园数据。本文档展示新 Tab 的形态、首屏结构与三段关键交互。 上层是结构化能力（找搭子、选课、就业经验、二手、问答），下层是兜底自由对话； 背后接的是种草 / 同校 Tab 的全量 UGC 与公开校园数据。本文档展示新 Tab 的形态、首屏结构与三段关键交互。

01 · 一句话定位

三个原则，决定了它长什么样

AI 学长 Tab 不是把 ChatGPT 塞进 App，也不是给"AI 规划 / AI 面试"换个皮。 它要回答一个非常窄的问题：本校学生此刻想做的撮合或决策，怎样最快得到答案。 我们用三个原则约束设计。

原则 01

只做撮合 + 决策

信息查询交给通用大模型，闲聊交给微信。我们只做本校精准的两件事：把人和人撮在一起，把决定帮人做出来。

原则 02

UGC 喂养，AI 输出

种草 / 同校 Tab 继续承担发帖入口，AI 在后台自动结构化每条帖子。用户问 AI，AI 替他从全站 UGC 里翻最准的本校答案。

原则 03

Agent 互碰，用户确认

找搭子、二手、失物，不是用户翻列表，是双方的 Agent 在后台撮合，匹配成功后再推给两个真人确认。

02 · 在底部 Tab 中的位置

把 AI 学长插在最左边，作为默认 Tab

原本的"种草 / 同校 / 就业 / 消息 / 我的"五 Tab 结构里， 就业 Tab 大幅瘦身合并进 AI 学长，"我的"暂时收起。 改造后五 Tab → 四 Tab，新 Tab 默认启动后第一个看到。

A · 找搭子撮合 — Agent 替你协商

找搭子是 9 月开学季的首场战役。AI 不是给你一个搜索结果列表， 而是把你的需求和别的同学需求互相撮合，匹配好以后再让两个真人确认。 这是通用大模型和小红书都做不了的事。

设计要点：所有 AI 输出都带引用 + 带行动。 不引用本校 UGC 的回答 = 通用大模型能给的回答 = 不是我们的差异化。 不带行动按钮的回答 = 用户看完什么也没干 = 不沉淀数据。

05 · 背后的事

UGC → 后台结构化 → AI 答案

AI 学长 Tab 不是凭空回答的。它的"本校精准"靠的是种草 / 同校 Tab 全量 UGC + 公开校园数据， 在后台被 AI 自动结构化成知识库。用户在前台问一句话，触发的是后台一整套检索 + 生成 + 撮合流程。

L1 · 数据生产

种草 + 同校 Tab

  • 种草自由帖（保留小红书形态）
  • 同校话题分区 + 模板帖
  • 课程评价 / 二手 / 失物
  • 实习 / 求职经验访谈
  • 公开校园数据（教务、活动）
自动结构化
L2 · 知识层

本校 RAG 知识库

  • 找搭子需求池（含未匹配）
  • 课程画像（老师 / 给分 / 评价）
  • 就业经验库（按学院 / 方向）
  • 二手商品池 + 信用分
  • 校园问答 FAQ（自动维护）
Agent 编排
L3 · 用户面前

AI 学长 Tab 答案

  • 找搭子 · Agent 互碰撮合
  • 选课 · 引用 + 推荐 + 一键导入
  • 就业 · 学长经验 + 简历 / 面试
  • 校园问答 · 兜底自由对话
  • 消息 Tab · 撮合结果推送

关键看点：种草 Tab 的发帖形态没变，但每条帖子在 AI 看来都被打过结构化标签。 用户视角："我刷了个帖"；AI 视角："本校语料池又多了一条可用数据"。 这是产品哲学层面的关键设计——让用户用熟悉的方式贡献数据，让 AI 用专业的方式消费数据。

06 · 时间线

Agent 不一次上齐，跟着学校节气走

AI 学长 Tab 的壳在 8 月底跟着 v2 一起上线，但里面的 Agent 不一次性铺满。 跟着学校的开学 / 秋招 / 考研 / 选课四个节气滚动上线，每一波都让一类用户最强烈感觉到"这个 App 是对的"。
